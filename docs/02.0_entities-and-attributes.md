# Clínica Salud Integral — Entidades y modelo de datos

## 1. Objetivo

Describir las cinco entidades implementadas en `prisma/schema.prisma`, incluidos sus atributos, tipos y relaciones. El esquema Prisma y la migración inicial son la referencia del modelo actual.

## 2. Entidades y atributos

Los tipos `String @db.Uuid` que aparecen como UUID se almacenan como `UUID` en PostgreSQL. Prisma crea las tablas con los nombres de modelo (`Patient`, `Doctor`, `Specialty`, `Appointment`, `User`) y conserva los nombres de columna camelCase, salvo el mapeo explícito `Appointment.scheduledAt` → `Appointment.startAt`.

### 2.1 Patient — Pacientes

| Atributo | Tipo Prisma / PostgreSQL | Descripción | Restricción |
|---|---|---|---|
| `id` | `String @db.Uuid` / `UUID` | Identificador del paciente. | PK, `@default(uuid())` |
| `firstName` | `String` / `TEXT` | Nombre. | Obligatorio |
| `lastName` | `String` / `TEXT` | Apellido. | Obligatorio |
| `email` | `String` / `TEXT` | Correo del paciente. | Obligatorio, único |
| `birthDate` | `DateTime @db.Date` / `DATE` | Fecha calendario de nacimiento. | Obligatorio |
| `phone` | `String?` / `TEXT` | Teléfono. | Opcional |

Relación: un paciente puede tener muchas citas (`appointments`).

### 2.2 Doctor — Médicos

| Atributo | Tipo Prisma / PostgreSQL | Descripción | Restricción |
|---|---|---|---|
| `id` | `String @db.Uuid` / `UUID` | Identificador del médico. | PK, `@default(uuid())` |
| `firstName` | `String` / `TEXT` | Nombre. | Obligatorio |
| `lastName` | `String` / `TEXT` | Apellido. | Obligatorio |
| `professionalLicense` | `String` / `TEXT` | Cédula profesional. | Obligatorio, único |
| `email` | `String?` / `TEXT` | Correo profesional. | Opcional |
| `specialtyId` | `String @db.Uuid` / `UUID` | Identificador de la especialidad. | FK, obligatorio |

Relaciones: cada médico pertenece a una especialidad, puede tener muchas citas y puede tener como máximo un usuario relacionado mediante la relación inversa `user`.

### 2.3 Specialty — Especialidades

| Atributo | Tipo Prisma / PostgreSQL | Descripción | Restricción |
|---|---|---|---|
| `id` | `String @db.Uuid` / `UUID` | Identificador de la especialidad. | PK, `@default(uuid())` |
| `name` | `String` / `TEXT` | Nombre de la especialidad. | Obligatorio, único |

Relación: una especialidad puede tener muchos médicos (`doctors`).

### 2.4 Appointment — Citas

| Atributo | Tipo Prisma / PostgreSQL | Descripción | Restricción |
|---|---|---|---|
| `id` | `String @db.Uuid` / `UUID` | Identificador de la cita. | PK, `@default(uuid())` |
| `patientId` | `String @db.Uuid` / `UUID` | Identificador del paciente. | FK, obligatorio |
| `doctorId` | `String @db.Uuid` / `UUID` | Identificador del médico. | FK, obligatorio |
| `scheduledAt` | `DateTime @db.Timestamptz(6)` / `TIMESTAMPTZ(6)` | Instante de la cita; su columna física se llama `startAt`. | Obligatorio |
| `reason` | `String?` / `TEXT` | Motivo de la cita. | Opcional |
| `status` | `AppointmentStatus` | Estado de la cita. | Obligatorio; default `PROGRAMADA` |

Relaciones: cada cita corresponde a un paciente y un médico. El esquema define índices no únicos por `(doctorId, scheduledAt)`, `(patientId, scheduledAt)` y `(status, scheduledAt)`.

### 2.5 User — Usuarios

| Atributo | Tipo Prisma / PostgreSQL | Descripción | Restricción |
|---|---|---|---|
| `id` | `String @db.Uuid` / `UUID` | Identificador del usuario. | PK, `@default(uuid())` |
| `email` | `String` / `TEXT` | Correo de acceso. | Obligatorio, único |
| `passwordHash` | `String` / `TEXT` | Hash de la contraseña. | Obligatorio |
| `role` | `UserRole` | Rol de la cuenta. | Obligatorio |
| `doctorId` | `String? @db.Uuid` / `UUID` | Médico vinculado, si corresponde. | FK, único y opcional |

La relación es `User.doctor` → `Doctor.user`. `doctorId` vive en `User`, no en `Doctor`.

## 3. Enums

`AppointmentStatus`: `PROGRAMADA`, `COMPLETADA`, `CANCELADA`. Las citas nuevas reciben `PROGRAMADA` por default.

`UserRole`: `RECEPCIONISTA`, `MEDICO`, `GERENCIA`.

## 4. Consideraciones del modelo implementado

- Las cinco claves primarias usan UUID generado por Prisma. Las claves foráneas también son UUID.
- `Patient.email`, `Doctor.professionalLicense`, `Specialty.name`, `User.email` y `User.doctorId` tienen restricciones únicas según el esquema. `Patient.email` es único en la implementación actual.
- Las relaciones son: `Patient` 1:N `Appointment`, `Doctor` 1:N `Appointment`, `Specialty` 1:N `Doctor` y `User` 0..1:0..1 `Doctor` mediante `User.doctorId`.
- `Patient.birthDate` es una fecha calendario (`DATE`), no una marca temporal.
- `Appointment.scheduledAt` es un instante (`TIMESTAMPTZ(6)`) y se persiste en la columna `startAt` por `@map("startAt")`.
- La migración inicial no declara unicidad compuesta para citas simultáneas. La regla funcional aprobada se documenta como requisito pendiente de implementación, no como restricción existente.
- Las tablas y columnas siguen los nombres creados por el esquema y la migración; no se aplican convenciones plurales o `snake_case` no declaradas.
