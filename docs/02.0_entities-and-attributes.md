Clínica Salud Integral — Entidades y modelo de datos
1. Objetivo
Identificar las entidades principales de la aplicación y definir la estructura de sus datos, incluyendo atributos, tipos de datos y restricciones necesarias para organizar la información en la base de datos.
2. Entidades y atributos
2.1 Patient — Pacientes
Almacena los datos personales de los pacientes.
Atributo	Tipo	Descripción	Restricción
id	Int	Identificador único del paciente.	PK, autoincremental
firstName	String	Nombre del paciente.	Obligatorio
lastName	String	Apellido del paciente.	Obligatorio
email	String	Correo electrónico del paciente.	Obligatorio
birthDate	Date	Fecha de nacimiento, sin componente de hora ni zona horaria.	Obligatorio


2.2 Doctor — Médicos
Almacena los datos de los médicos registrados en la clínica.
Atributo	Tipo	Descripción	Restricción
id	Int	Identificador único del médico.	PK, autoincremental
firstName	String	Nombre del médico.	Obligatorio
lastName	String	Apellido del médico.	Obligatorio
specialtyId	Int	Identificador de la especialidad del médico.	FK, obligatorio
userId	Int?	Identificador de la cuenta de acceso vinculada.	FK, único y opcional


2.3 Specialty — Especialidades
Almacena el catálogo de especialidades médicas.
Atributo	Tipo	Descripción	Restricción
id	Int	Identificador único de la especialidad.	PK, autoincremental
name	String	Nombre de la especialidad.	Obligatorio


2.4 Appointment — Citas
Almacena la información de las citas médicas.
Atributo	Tipo	Descripción	Restricción
id	Int	Identificador único de la cita.	PK, autoincremental
patientId	Int	Identificador del paciente.	FK, obligatorio
doctorId	Int	Identificador del médico.	FK, obligatorio
scheduledAt	DateTime	Instante de la cita; se almacena como `timestamptz(3)` en PostgreSQL y usa `@db.Timestamptz(3)` en Prisma.	Obligatorio
reason	String?	Motivo de la cita.	Opcional
status	AppointmentStatus	Estado de la cita.	Obligatorio, valor predeterminado PROGRAMADA


2.5 User — Usuarios
Almacena las cuentas de acceso al sistema.
Atributo	Tipo	Descripción	Restricción
id	Int	Identificador único del usuario.	PK, autoincremental
email	String	Correo electrónico de acceso.	Obligatorio, único
password	String	Contraseña almacenada mediante hash.	Obligatorio
role	Role	Rol asignado al usuario.	Obligatorio


3. Valores enumerados
Los siguientes enums establecen los valores permitidos para determinados atributos.
3.1 AppointmentStatus
Define los estados posibles de una cita:
- PROGRAMADA
- COMPLETADA
- CANCELADA
Toda cita nueva tendrá el estado PROGRAMADA de manera predeterminada.
3.2 Role
Define los roles disponibles para las cuentas de usuario:
- RECEPCIONISTA
- MEDICO
- GERENCIA
4. Consideraciones del modelo de datos
- Claves primarias (PK): cada tabla tendrá un campo id de tipo Int, autoincremental, para identificar sus registros.
- Claves foráneas (FK): los campos specialtyId, patientId, doctorId y userId permitirán referenciar registros de otras tablas.
- Campos obligatorios: los atributos marcados como obligatorios no podrán quedar sin valor.
- Campos opcionales: reason y userId podrán almacenar valores nulos.
- Correo de acceso: el campo `User.email` será único para evitar cuentas duplicadas. El modelo Prisma `User` se mapea a la tabla física `users`.
- Vinculación de médicos: un médico podrá existir sin una cuenta de acceso. Cuando tenga una cuenta vinculada, esta relación será única y corresponderá a un usuario con rol MEDICO. Toda cuenta con rol MEDICO deberá estar vinculada a un registro `Doctor`. La validación del rol y de la obligatoriedad de la relación se realizará desde la lógica de la aplicación.
- Identificadores: las cinco entidades utilizarán claves primarias de tipo Int autoincremental.
- Contraseñas: se almacenarán mediante hash utilizando bcryptjs, nunca como texto plano.
- Estado de las citas: al crear una cita, el estado se asignará automáticamente como PROGRAMADA.
- Citas simultáneas: el modelo Prisma `Appointment` tendrá dos restricciones únicas compuestas: (doctorId, scheduledAt) y (patientId, scheduledAt). Aplican a todos los estados y comparan el instante almacenado en UTC. Prisma generará las restricciones en PostgreSQL mediante `@@unique`.
- Tipos temporales: `Patient.birthDate` se almacena como `DATE` en PostgreSQL y `@db.Date` en Prisma. Los campos que representan instantes, incluido `Appointment.scheduledAt`, se almacenan como `timestamptz(3)` en PostgreSQL y usan `@db.Timestamptz(3)` en Prisma.
- Nombres SQL: los modelos Prisma serán singulares (`Patient`, `Doctor`, `Specialty`, `Appointment`, `User`) y se mapearán a las tablas físicas plurales (`patients`, `doctors`, `specialties`, `appointments`, `users`) mediante `@@map`. Los atributos camelCase que tengan más de una palabra usarán columnas `snake_case` mediante `@map`.
